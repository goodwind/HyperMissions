**Права приложений для Android TV, в прошивке которых нет для них экрана.**

## Зачем

В некоторых прошивках телевизоров нет штатных экранов Android «О приложении» и разрешений. В Xiaomi
HyperOS на MiTV-MFTR0 (Android 11), например, нет ни «О приложении», ни «Доступа ко всем файлам», ни
«Поверх других окон». Поэтому:

- разрешение нельзя ни выключить, ни включить;
- приложения, которые отправляют вас на эти экраны, показывают «Ошибка» (так делает «Файловый менеджер+»,
  когда просит доступ к памяти) и настроить их нельзя совсем.

HyperMissions — это недостающий экран, оформленный как обычное приложение.

## Что умеет

**Приложения карточками:** иконка, название и сколько разрешений включено (`Вкл: 3/4`). *Установленные*
показывает то, что вы поставили на телевизор, *Все* — каждый пакет.

**Одно приложение:** версия и дата установки; **Открыть**, **Остановить**, **Очистить данные** (нажать
дважды) и **Удалить**; его разрешения по видам (камера, микрофон, контакты, геолокация, файлы и медиа,
телефон, SMS...) и особые доступы, которые оно запрашивает. OK на строке включает или выключает.

<p align="center"><img src="docs/img/panel.png" width="70%" alt="Одно приложение: действия и разрешения"></p>

**Отвечает приложениям, которые просят эти экраны.** Когда приложение отправляет вас в «О приложении»,
«Доступ ко всем файлам», «Поверх других окон», «Изменение системных настроек» или «Установку неизвестных
приложений», поверх него открывается панель только с тем, что выключено, а «Назад» возвращает в
приложение.

## Установка

1. Скачайте `HyperMissions-1.0.0.apk` из [последнего релиза](https://github.com/goodwind/HyperMissions/releases/latest).
2. Установите его на телевизор. С компьютера в той же сети:

   ```bash
   adb connect <ip-телевизора>:5555
   adb install HyperMissions-1.0.0.apk
   ```

   или скопируйте файл на телевизор и откройте его файловым менеджером.
3. Откройте **HyperMissions** в списке приложений телевизора.

Проверить загрузку можно по подписи: APK подписан ключом, SHA-256 сертификата которого

```
F3:93:9E:A0:02:8E:B3:82:93:B5:0C:F1:98:56:9C:CC:EB:0C:EE:4E:9A:31:19:2D:48:90:CA:8F:D1:9C:C0:D2
```

(`apksigner verify --print-certs HyperMissions-1.0.0.apk`). Обновление встаёт только поверх копии,
подписанной тем же ключом.

### Одна настройка на телевизоре: отладка ADB по сети

Менять разрешения другого приложения может только системная оболочка (см.
[Как это работает](#как-это-работает)), поэтому на телевизоре должна быть включена отладка ADB, доступная
приложению по адресу `127.0.0.1:5555`. На большинстве телевизоров это *Для разработчиков → Отладка по
USB / ADB*. Если приложение пишет «Для изменения разрешений нужна отладка по ADB», она выключена, либо
телевизор не слушает порт 5555; с компьютера `adb tcpip 5555` включает её до перезагрузки телевизора.

При первом изменении телевизор спросит **«Разрешить отладку по USB?»** для собственного ключа
HyperMissions. Поставьте **«Всегда разрешать»** и выберите **«Разрешить»**.

Для просмотра разрешений (список и панели) всё это не нужно.

## Как пользоваться

- **Список:** стрелки для перемещения, OK открывает приложение, «Назад» выходит. Вверху *Установленные* / *Все*.
- **Панель:** OK на разрешении или особом доступе включает или выключает его (сразу весь вид: включив
  *Контакты*, вы даёте всё, что приложение просит в этом виде). OK на **Очистить данные** дважды; это
  нельзя отменить. **Удалить** передаёт управление штатному подтверждению Android.
- Изменение разрешения заставляет Android перезапустить приложение, как и в системном экране.

## Как это работает

Для выдачи или отзыва разрешения другого приложения нужно право `GRANT_RUNTIME_PERMISSIONS`, которое есть
только у **оболочки** (shell), а не у приложения. Поэтому HyperMissions говорит по протоколу ADB с `adbd`
самого телевизора на `127.0.0.1:5555` (с собственным ключом, который хранится в закрытом хранилище
приложения) и просит оболочку это сделать.

Это возможность, на которую стоит смотреть внимательно, поэтому приложение намеренно **не является
универсальной оболочкой**. Оно может отправить только такие команды:

- `pm grant|revoke <пакет> <разрешение>`
- `appops set [--uid] <пакет> <операция> allow|deny`, операция из списка из четырёх
- `am force-stop <пакет>` и `pm clear <пакет>`

Имена пакета и разрешения должны соответствовать шаблону точечных идентификаторов, операции берутся из
фиксированного списка, передать строку команды нельзя. Код в
[`AdbShell.kt`](app/src/main/java/io/github/goodwind/hypermissions/AdbShell.kt). Что разрешает ключ и как
его отозвать, см. в [SECURITY](SECURITY.md).

Чтение использует обычные `PackageManager` и `AppOpsManager`, без привилегий.

## Чего оно не умеет

- **Очищать кэш.** В Android 11 у `pm clear` нет `--cache-only`: опция игнорируется, и стираются **все**
  данные приложения. `pm trim-caches` работает не по приложению. Поэтому такой кнопки нет.
- **Убирать приложение из «Недавних»** после остановки: в Android 11 для этого нет команды.
- **Особые доступы на Android 9 и старше**: они появились с Android 10, этих строк не будет.
- Для изменений телевизор должен давать приложению доступ к своему `adbd`. Просмотр работает везде.

## Проверено на

- Xiaomi MiTV-MFTR0, HyperOS (Android 11): всё перечисленное выше.

Другие телевизоры и версии Android не проверялись; сообщения о них приветствуются.

## Сборка

JDK 17 и Android SDK (платформа 36):

```bash
./gradlew assembleRelease
```

APK лежит в `app/build/outputs/apk/release/`. Релиз подписывается ключом из `local/signing.properties`
(`storeFile`, `storePassword`, `keyAlias`, `keyPassword`; не хранится в репозитории). Без этого файла
сборка использует ваш отладочный ключ: она установится, но обновить релиз не сможет. См.
[CONTRIBUTING](CONTRIBUTING.md).

## Связанное

- [Aerial](https://github.com/pengchujin/aerial-tv) — лаунчер для Android TV. Pull request добавляет в него
  такую же панель «О приложении» ([#233](https://github.com/pengchujin/aerial-tv/pull/233)). Если
  установлены оба, на системный запрос «О приложении» отвечает только один, поэтому Android не спрашивает,
  чем открыть.
